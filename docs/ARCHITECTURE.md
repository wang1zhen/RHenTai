# RHenTai Architecture

RHenTai is a cross-platform reader for e-hentai.org (EH) and exhentai.org (EX), built with Rust and Tauri 2
and a React frontend. It targets Linux, Windows and macOS now, and keeps the code ready for Tauri's
Android/iOS targets later.

Feature scope: login, browsing and search, gallery details, online reading, favorites management,
batch download with resume, a local library (downloaded galleries, image folders, zip/cbz archives),
history, and settings.

Reference clients: JHenTai (Flutter) and EhViewer (Android). The wire protocol is in `docs/EH_PROTOCOL.md`;
the frontend/backend contract is in `docs/IPC.md`. When documents disagree, `IPC.md` wins for types and
command names, and `EH_PROTOCOL.md` wins for site behaviour.

## 1. Principles

1. **Rust owns the network, parsing, persistence and file IO.** The webview never calls e-hentai directly,
   so cookies, CORS, Cloudflare detection, rate limiting and caching are handled once, in Rust.
2. **Tauri-free core.** Everything except IPC and window glue lives in plain Rust crates that tests, the
   CLI and future mobile targets can all use.
3. **One contract.** IPC types are defined once in Rust and exported to TypeScript with `ts-rs`. The
   frontend never hand-writes a type that crosses IPC.
4. **Polite client.** Page and API requests go through a global rate limiter, and concurrency is bounded,
   to avoid IP bans. The defaults are conservative.
5. **Mobile-ready.** Core paths use no desktop-only API. Desktop-only features (opening a folder in the
   file manager, the login window) sit behind `#[cfg(desktop)]` or a capability check, and the UI is
   responsive down to phone widths.

Dependency direction (must not be violated):

```
src (React) --IPC--> src-tauri --> rhentai-core --> eh-client
                    rhentai-cli --> rhentai-core --> eh-client
```

`eh-client` must not depend on SQLite, Tauri or the filesystem layout. `rhentai-core` must not depend on
Tauri. `src-tauri` holds no business logic: every command is a thin call into `rhentai-core`.

## 4. eh-client (protocol library)

`EhClient` is cheap to clone (`Arc` inside) and holds the reqwest client, the cookie jar, the current
`Site`, and the rate limiter.

```rust
pub struct ClientConfig {
    pub proxy: Option<String>,          // http://, https://, socks5://, socks5h://
    pub user_agent: Option<String>,     // default: a current desktop Chrome UA string
    pub cookie_path: Option<PathBuf>,   // None = in-memory jar (tests)
    pub site: Site,
    pub min_request_interval_ms: u64,   // default 350, applied to HTML pages and api.php
}

impl EhClient {
    pub fn new(cfg: ClientConfig) -> Result<Self>;
    pub fn site(&self) -> Site;
    pub fn set_site(&self, site: Site);

    // auth (docs/EH_PROTOCOL.md §2)
    pub async fn auth_status(&self, verify_online: bool) -> Result<AuthStatus>;
    pub async fn login_password(&self, req: &PasswordLogin) -> Result<AuthStatus>;
    pub async fn login_cookies(&self, req: &CookieLogin) -> Result<AuthStatus>;
    pub fn import_cookies(&self, cookies: &[RawCookie]) -> Result<()>;     // used by the web-login window
    pub fn logout(&self) -> Result<()>;

    // browsing
    pub async fn list(&self, req: &ListRequest) -> Result<GalleryListPage>;
    pub async fn gallery_detail(&self, key: &GalleryKey) -> Result<GalleryDetail>;
    pub async fn thumbnails(&self, key: &GalleryKey, page: u32) -> Result<ThumbnailPage>;
    pub async fn page_image(&self, key: &GalleryKey, page: &PageRef, reload_key: Option<&str>) -> Result<PageImage>;
    pub async fn fetch_image(&self, url: &str, referer: Option<&str>) -> Result<FetchedImage>; // bytes + content type

    // favorites
    pub async fn favorite_categories(&self) -> Result<Vec<FavoriteCategory>>;
    pub async fn set_favorite(&self, key: &GalleryKey, slot: Option<u8>, note: &str) -> Result<()>;
    pub async fn batch_favorites(&self, gids: &[u64], slot: Option<u8>) -> Result<()>;   // None = delete

    // api.php
    pub async fn gdata(&self, keys: &[GalleryKey]) -> Result<Vec<GallerySummary>>;     // chunks of 25
}
```

### List strategy (robust against the user's display mode)

The site renders lists in five display modes (minimal, minimal+, compact, extended, thumbnail), chosen by
the account profile. RHenTai does not depend on the mode:

1. The HTML parser extracts, in page order, every gallery identity `(gid, token)` from `/g/{gid}/{token}/`
   anchors inside `.itg`. It also extracts the per-item favorite marker (`[id^=posted_]`, title plus
   border colour) and the cursors (`#unext`, `#uprev` hrefs). It detects `No hits found` and the special
   pages listed in EH_PROTOCOL §5.
2. Metadata (title, Japanese title, category, thumbnail, uploader, posted, file count, rating, tags,
   expunged) comes from `api.php` `gdata`, in batches of 25, keeping the HTML order.
3. If `gdata` fails, the client falls back to best-effort HTML fields (title from `.glink`, category from
   `.cn`/`.cs`, thumbnail from `img[data-src|src]`) instead of failing the whole page.

### Detail and pages

`gallery_detail` parses `/g/{gid}/{token}/` (with cookie `nw=1` so content warnings are skipped). It
returns metadata, tag groups, comments, the current favorite slot and note, and thumbnail page 0
(`PageRef`s: page token, sprite rectangle, file name). `thumbnails(key, p)` fetches `?p=p`.
`page_image` fetches `/s/{page_token}/{gid}-{index+1}` (adding `nl=<reload_key>` on retry) and parses
the image URL, the size, the next reload key and the original-image link.

## 5. rhentai-core (application services)

```rust
pub struct Core {           // Clone (Arc inside); created once by src-tauri or the CLI
    pub paths: AppPaths,    // data_dir, config_dir, cache_dir, default download dir
    pub settings: SettingsStore,
    pub client: EhClient,   // rebuilt on proxy change; site switched on settings change
    pub store: Store,       // SQLite
    pub images: ImageService,
    pub downloads: DownloadManager,
    pub library: Library,
    pub history: History,
}
pub trait EventSink: Send + Sync + 'static { fn emit(&self, event: CoreEvent); }
pub enum CoreEvent { DownloadProgress(DownloadProgress), DownloadsChanged, LibraryChanged, AuthChanged(AuthStatus) }
```

`Core::open(paths, sink: Arc<dyn EventSink>)` loads settings, opens or migrates the DB, builds the client,
and resumes downloads that were `running` when the app quit (they become `queued`, then the scheduler
starts them).

### AppPaths

The Tauri shell uses Tauri's resolver (`app_data_dir`, `app_config_dir`, `app_cache_dir`, `download_dir`).
The CLI mirrors the same locations with the `dirs` crate and identifier `com.rhentai.app`, so the CLI and
the app share one login and one library. `--data-dir` overrides this for tests and QA.

### SQLite schema (migration 1)

```sql
CREATE TABLE downloads (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  gid INTEGER NOT NULL UNIQUE, token TEXT NOT NULL, site TEXT NOT NULL,
  title TEXT NOT NULL, thumb TEXT NOT NULL, category TEXT NOT NULL,
  total INTEGER NOT NULL DEFAULT 0, done INTEGER NOT NULL DEFAULT 0, failed INTEGER NOT NULL DEFAULT 0,
  state TEXT NOT NULL, error TEXT, dir TEXT NOT NULL, original INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);
CREATE TABLE download_pages (
  download_id INTEGER NOT NULL REFERENCES downloads(id) ON DELETE CASCADE,
  idx INTEGER NOT NULL, page_token TEXT, file_name TEXT, state TEXT NOT NULL, error TEXT, bytes INTEGER,
  PRIMARY KEY (download_id, idx)
);
CREATE TABLE history (
  key TEXT PRIMARY KEY,               -- "online:<gid>" or "local:<id>"
  gid INTEGER, token TEXT, local_id TEXT,
  title TEXT NOT NULL, thumb TEXT, category TEXT,
  page_count INTEGER NOT NULL, last_page INTEGER NOT NULL, read_at INTEGER NOT NULL
);
CREATE TABLE local_galleries (
  id TEXT PRIMARY KEY,                -- first 16 hex chars of sha256(canonical path)
  path TEXT NOT NULL UNIQUE, kind TEXT NOT NULL, title TEXT NOT NULL, page_count INTEGER NOT NULL,
  gid INTEGER, token TEXT, category TEXT, tags_json TEXT NOT NULL DEFAULT '[]',
  downloaded INTEGER NOT NULL DEFAULT 0, mtime INTEGER NOT NULL, added_at INTEGER NOT NULL
);
```

### ImageService (online reading + thumbnails)

- `thumb(url) -> Bytes`: disk cache `<cache>/thumbs/<sha1(url)>`, fetched through `EhClient` (EX thumbnails
  need cookies).
- `page(gid, token, index) -> Bytes`:
  1. If the gallery is downloaded and the page file exists, serve it from disk.
  2. Otherwise resolve `PageRef` (detail page `index / thumbs_per_page`, cached in memory per gallery),
     then the `PageImage` (cached in memory), then fetch the image into `<cache>/pages/<gid>/<index>`.
  3. Concurrency: at most 4 in-flight page resolutions, plus the client's rate limiter.
- `reload(gid, token, index)`: drop cached bytes and the cached `PageImage`; the next `page()` passes the
  stored `reload_key` (`nl`) to get a different H@H node.
- The page cache is capped (default 2 GiB, oldest-first eviction at startup and after writes). Settings has
  "clear cache".
- If the resolved URL is the 509 image, return `ErrorKind::ImageLimit`.

### DownloadManager (batch download)

- A task is one gallery. States: `queued → running → completed | failed | paused`. Tasks and per-page rows
  are persisted, so restarts resume.
- Scheduler: at most 2 galleries `running` at once. A global image semaphore of size
  `settings.download_concurrency` (default 4, range 1-10) is shared by all running tasks.
- Per task: fetch the detail (title, page count, thumbs-per-page), create
  `<download_dir>/<gid> - <sanitized title>/`, enumerate `PageRef`s across detail pages, then for each page
  not yet `done`: resolve the `PageImage`, download it to `NNNN.<ext>.part`, fsync, rename to
  `NNNN.<ext>` (1-based, zero-padded to 4 digits, extension from Content-Type, falling back to the URL),
  and mark the row `done`. Up to 5 attempts per page; on failure re-resolve with `nl`. HTTP 403 means a
  dead H@H node and goes straight to re-resolve.
- 509 or "exceeded your image" pauses every task with error `ImageLimit`. A ban pauses everything with
  `Banned`.
- On completion, write `rhentai.json` (gallery metadata, see §7), upsert the library entry, and emit
  `LibraryChanged`.
- Progress events are throttled to 4 per second per task, plus one on every state change.
- Pause cancels in-flight requests through a per-task `CancellationToken`; `.part` files are deleted on
  resume.
- `remove(id, delete_files)` removes the DB rows and optionally the directory (only if it lies inside the
  configured download dir).
- Title sanitizing: replace `<>:"/\|?*` and control characters with a space, collapse whitespace, trim
  trailing dots and spaces, and cap at 150 bytes on a UTF-8 boundary.

### Library (local reading)

- Roots: `settings.download_dir` plus `settings.library_dirs`.
- Scan (depth ≤ 3; symlinks not followed). A gallery is either:
  - a directory containing at least one image file (`jpg jpeg png gif webp avif bmp`) directly inside it;
    if it holds `rhentai.json`, title, gid, token, category and tags come from that file
    (`downloaded = true`); or
  - a `.zip` or `.cbz` file with at least one image entry.
- Pages are sorted with natural ordering (`natord`). Hidden files and `.part` files are ignored.
- A corrupt archive is skipped with a logged warning and never aborts the scan. Empty directories are
  ignored.
- `page(id, index)` reads the file, or the zip entry, with the Content-Type sniffed from magic bytes.
- `remove(id, delete_files)` deletes files only for entries inside a configured root.

### Settings

```rust
pub struct Settings {               // defaults in brackets
    pub site: Site,                     // [eh]
    pub proxy: Option<String>,          // [None]
    pub download_dir: String,           // [<system Downloads>/RHenTai]
    pub download_concurrency: u8,       // [4], clamp 1..=10
    pub download_original: bool,        // [false]
    pub library_dirs: Vec<String>,      // [[]]
    pub reader: ReaderSettings,         // [mode vertical, direction ltr, fit width, preload 3]
    pub theme: Theme,                   // [system]
    pub language: UiLanguage,           // [zh-CN]
}
```

`update_settings` validates the proxy URL (scheme must be http, https, socks5 or socks5h), clamps
numbers, creates `download_dir`, rebuilds the client when the proxy changed, and switches the site.
Switching to EX without EX access is allowed, but lists then return `NoExAccess`.

## 6. src-tauri (shell)

- `lib.rs`: `#[cfg_attr(mobile, tauri::mobile_entry_point)] pub fn run()`; `main.rs` calls
  `rhentai_lib::run()`. The crate type is `["staticlib", "cdylib", "rlib"]`.
- `setup`: resolve paths, `Core::open(paths, Arc::new(TauriSink(app_handle)))`, `app.manage(core)`.
- Commands are `async fn name(core: State<'_, Core>, req: T) -> Result<R, IpcError>`, registered in one
  `generate_handler!`. Names and types are in `docs/IPC.md`.
- `protocol.rs`: `register_asynchronous_uri_scheme_protocol("rhimg", …)` serves thumbnails, online pages
  and local pages (routes in IPC.md §4). Responses carry `Content-Type`; errors return 404 or 502 with a
  short text body.
- `login_window.rs` (desktop only) opens a `WebviewWindow` labelled `login` on the forums login page,
  polls `cookies_for_url` every second until `ipb_member_id` and `ipb_pass_hash` exist, then navigates to
  `https://exhentai.org/` and waits up to 20 s for `igneous`. It imports the cookies into `EhClient`,
  verifies them, emits `auth-changed`, and closes the window. If the user closes the window first, it
  stops quietly.
- `tauri.conf.json`: productName `RHenTai`, identifier `com.rhentai.app`, one main window (1280×800, min
  420×600), and a CSP that allows `img-src 'self' data: blob: rhimg: http://rhimg.localhost https://rhimg.localhost`.
- Capabilities: core defaults, `dialog:allow-open`, `opener:default`, event listen. The `login` window is
  remote content and gets **no** IPC capability.

## 7. On-disk formats

`rhentai.json` (inside each downloaded gallery directory):

```json
{ "version": 1, "site": "eh", "gid": 123, "token": "abcdef0123", "title": "…", "titleJpn": "…",
  "category": "manga", "uploader": "…", "posted": 1700000000, "tags": [{"namespace":"female","name":"glasses"}],
  "pageCount": 24, "pages": ["0001.jpg", "0002.png"], "downloadedAt": 1791960000, "original": false }
```

`cookies.json`: cookie_store JSON (secrets, mode 0600). `settings.json`: the `Settings` JSON. `rhentai.db`:

## 8. Frontend

- Routing (HashRouter): `/` home, `/popular`, `/toplist`, `/watched`, `/favorites`,
  `/gallery/:gid/:token`, `/read/online/:gid/:token?page=N`, `/read/local/:id?page=N`, `/downloads`,
  `/library`, `/history`, `/settings`, `/login`.
- Layout: a left sidebar at ≥ 768 px and a bottom tab bar below that. The top bar holds the search box, an
  EH/EX switch and the account chip.
- Data: TanStack Query wraps every IPC call (`useInfiniteQuery` with `next` cursors for lists). Download
  progress comes from events into a zustand store. Settings come from a query and are written back with
  `update_settings`.
- Gallery grid: virtualized (TanStack Virtual) cards showing the thumbnail (`rhimg` thumb URL), category
  colour, title, rating stars, page count, uploader and date. Multi-select mode supports batch download,
  batch move to a favorite slot, and batch removal.
- Detail: cover, both titles, a metadata table, tags grouped by namespace (click to search), and the
  actions Read / Continue (from history) / Download / Favorite (slot and note dialog) / Open in browser.
  Below that, the thumbnail grid (sprites rendered with `background-position`, paged) and comments.
- Reader: full screen. Vertical continuous (virtualized) or paged (LTR/RTL). Fit width, height or
  original. Preloads N pages. Keyboard: arrows, PageUp/PageDown, Space, Home/End, Esc. A click on the
  left or right third flips the page; touch swipes work. An overlay shows the page slider and settings. A
  failed image shows a retry button that calls `reload_page_image` and bumps the `?v=` URL param.
  Progress is saved through `record_progress`, debounced to 1 s.
- Favorites: slot tabs with names and counts, a list with multi-select, and a "login required" empty
  state.
- Downloads: task rows with a progress bar, speed, state, error, Pause/Resume/Remove (optionally deleting
  files), Read and Open folder, plus Pause all and Resume all.
- Library: grid of covers (`rhimg local/<id>/0`), a filter box, Rescan, Add folder (dialog), Read, Remove.
- Settings: site, proxy, download dir (folder picker), concurrency, original images, reader defaults,
  theme, language, library folders, clear image cache, account (login and logout).
- Login page: tabs for Web login (recommended), Cookie, and Password (shows the Cloudflare hint on
  `cloudflare` errors).
- i18n: a typed dictionary for `zh-CN` (default) and `en`.
- Category colours: doujinshi #9E2720, manga #DB6C24, artistCg #D38F1D, gameCg #6A936D, western #AB9F60,
  nonH #5FA9CF, imageSet #325CA2, cosplay #6A32A2, asianPorn #A23282, misc #777777, private #000000.

## 9. Errors

`ErrorKind` (serialized camelCase): `network, http, parse, cloudflare, banned, loginRequired, loginFailed,
noExAccess, imageLimit, notFound, invalidInput, io, db, cancelled, internal`. `IpcError { kind, message }`
is what every command returns on failure. The UI maps `kind` to a localized headline and shows
`message` as detail.

## 10. Testing and QA

- `eh-client`: parser unit tests run against saved HTML fixtures in `crates/eh-client/tests/fixtures/`
  (captured live, trimmed, no cookies inside). URL and form builder tests. `tests/live.rs` is
  `#[ignore]` unless `RHENTAI_LIVE=1`.
- `rhentai-core`: store/migration tests on a temp DB; library scan tests on temp dirs (image folder, cbz,
  corrupt zip, empty dir); title-sanitizer tests; a download-manager test against a local fake page
  source (trait `PageSource`), covering resume and pause.
- `rhentai-cli`: the real-surface QA entry for the core (list/detail/image/download/library); see
  `docs/IPC.md` §5.
- Frontend: `pnpm typecheck` and `pnpm build`.
- App: `pnpm tauri dev` / `pnpm tauri build --debug --no-bundle`, exercised through the real window.
- CI (`.github/workflows/ci.yml`): fmt, clippy, tests and the frontend build on ubuntu-latest,
  windows-latest and macos-latest.

## 11. Mobile readiness checklist

- The `run()` mobile entry point exists. No `std::process::Command` and no desktop-only crates in
  `rhentai-core`/`eh-client`.
- Paths always come from `AppPaths`; there are no hard-coded `~`.
- The `login_window` and `open_path` commands are behind `#[cfg(desktop)]`. On mobile they return
  `invalidInput` ("not supported on this platform").
- The UI uses responsive breakpoints and touch gestures in the reader.
